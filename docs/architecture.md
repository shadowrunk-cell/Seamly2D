# SeamlyAI — Архитектурный обзор (для ревью)

Этот документ — сжатая выжимка для параллельного архитектурного ревью.
Цель: дать ревьюеру полный контекст стека, принятых решений и открытых вопросов,
чтобы он мог предложить улучшения и найти промахи без чтения всего C++ кода.

## 1. Что такое SeamlyAI

Форк **Seamly2D** (C++/Qt CAD для конструирования одежды) с AI-функциями.

- **Логотип/суть**: пользователь вводит мерки (ОГ / ОТ / ОБ / рост) → получает готовое
  лекало (файл `.val` + мерки `.vit`), готовое к 3D-среде (CLO 3D, Blender).
- **НЕ цель**: переписать CAD-ядро. Цель — AI-функции и упрощённый UX вокруг готового ядра.
- **Монетизация**: Freemium.

Форк: `FashionFreedom/Seamly2D` → `shadowrunk-cell/Seamly2D`.

## 2. Технологический стек и архитектура

```
┌─────────────────────────────────────────────────────────────────┐
│  SeamlyAI                                                       │
│                                                                 │
│  ┌────────────────────┐    ┌───────────────────────────────┐    │
│  │  C++/Qt core        │    │  AI-Service (Python/FastAPI)  │    │
│  │  (форк Seamly2D)    │    │                               │    │
│  │  читает/пишет       │◄──►│   - LLM-чат (text + vision)  │    │
│  │  .val / .vit        │    │   - генерация лекал по шаблонам│   │
│  └────────────────────┘    │   - провайдер-абстракция       │    │
│                            └───────────┬───────────────────┘    │
│                                        │                        │
│                            ┌───────────▼───────────────────┐    │
│                            │  Веб-UI (React/TS, future)    │    │
│                            └───────────────────────────────┘   │
│                                                                 │
│  3D: DXF-ASTM / OBJ / FBX  →  CLO 3D, Blender                  │
└─────────────────────────────────────────────────────────────────┘
```

### Основные слои:
1. **Core (C++/Qt)** — унаследован от Seamly2D. Мы его почти не трогаем.
2. **AI-Service (Python/FastAPI)** — вся наша новая ценность:
   - `app/providers/` — абстракция LLM (OpenAI-compat + Anthropic)
   - `app/pattern/` — генерация лекал (шаблоны, мерки, adjustments)
   - `app/routes/` — REST API
   - `app/static/` — веб-чат (MVP на HTML/JS)
3. **templates/** — реальные `.val`-шаблоны (лиф, юбка, брюки)

## 3. Ключевые архитектурные решения

### Решение 1: Провайдер-агностик (не хардкодим LLM)
- **Почему**: у пользователя много провайдеров (OpenCode, локальные модели, Сбер/GigaChat, Ollama, Azure, vLLM).
- **Как**: конфиг `providers.yaml` описывает провайдеров и роли моделей (`text`, `vision`, `image`).
  Никакого хардкода конкретной модели в коде. Одна модель может закрывать несколько ролей.
- **Сильные стороны**: смена LLM = правка YAML, без пересборки.
- **Открытый вопрос**: нет API-ключа-агностика по умолчанию; ожидаем ключ из env.

### Решение 2: Генерация лекал "по шаблонам", а не свободный VIT
- **Почему**: свободная генерация VIT ненадёжна. Шаблоны дают рабочий результат сразу.
- **Как**: берём реальный `.val` (из установленного образца) → заменяем мерки в `.vit`
  и применяем уточнения (adjustments). Результат — валидный XML, который открывается в Seamly2D.
- **Сильные стороны**: детерминированно, работает без LLM, тестируемо офлайн.
- **Открытый вопрос**: нужен ли авто-обвес ткани (outline/flip по контуру) — Phase 2.

### Решение 3: Разделение ядра и AI-слоя
- **Почему**: чтобы не тащить вечную синхронизацию с upstream (это острая боль форков).
- **Как**: AI-сервис — отдельный микросервис, не зависит от кода Seamly. Upstream обновления
  тянем редко и адресно (только полезные фиксы вроде экспорта).
- **Сильные стороны**: AI не ломается от обновлений C++ ядра; можно развивать независимо.

### Решение 4: Каждая фаза — отдельная итерация с OpenSpec
- Полная цепочка: `proposal → task → spec` в `openspec/`. Validate OpenSpec в CI.

## 5. Открытые вопросы (кандидаты на ревью-фидбек)

1. **Синхронизация с upstream** — как правильно и автоматически тянуть обновления Seamly2D
   и не сломать собственные изменения. Rebasing vs merge стратегия.
2. **Безопасность провайдеров** — управление API-ключами (env, secrets-менеджмент, vault).
   providers.yaml содержит ключи — есть риск утечки. Нужен ли менеджер секретов?
3. **Валидация лекал** — как тестировать, что сгенерированный `.val` корректен в Seamly2D
   без ручного открытия? (golden-файлы, schema-валидация, снэпшот-тесты.)
4. **Vision-пайплайн** — как надёжно переводить фото/эскиз в мерки (замеры с фото?).
5. **Масштабирование** — YAML-шаблоны лекал: API для добавления новых шаблонов без кода.
6. **Роли моделей** — хватает ли text/vision, нужен ли отдельный "planner"/"router" для LLM
   (последовательность шагов: промпт → каркас лекала → финал)?

## 6. Файлы для точечного ревью

- `ai-service/app/pattern/generator.py` — ядро генерации лекал (regex-подстановка в XML).
- `ai-service/app/pattern/measurements.py` — стандартные размеры, вывод производных мерок.
- `ai-service/app/providers/*.py` — адаптеры LLM.
- `ai-service/app/routes/*.py` — REST API.
- `ai-service/providers.example.yaml` — пример конфигурации провайдеров.
- `ai-service/tests/test_generator.py` — офлайн-тесты (без LLM).
- `openspec/project.md`, `openspec/AGENTS.md` — цель и правила.

1. Создай в GitHub **fine-grained PAT** (только Read: Contents, только этот репозиторий).
2. Дай токен DeepSeek-интеграции как GitHub-токен для чтения.

   ревью + предложи улучшения».
