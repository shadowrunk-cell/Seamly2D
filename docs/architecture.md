# SeamlyAI — Архитектурный обзор (для ревью)

Этот документ — сжатая выжимка для параллельного архитектурного ревью.
Цель: дать ревьюеру полный контекст стека, принятых решений и открытых вопросов,
чтобы он мог предложить улучшения и найти промахи без чтения всего C++ кода.

## 1. Что такое SeamlyAI

Форк **Seamly2D** (C++/Qt CAD для конструирования одежды) с AI-функциями.

- **Логотип/суть**: пользователь вводит мерки (ОГ / ОТ / ОБ / рост) → получает готовое
  лекало (файл `.val`/`.sm2d` + мерки `.vit`), готовое к 3D-среде (CLO 3D, Blender).
- **НЕ цель**: переписать CAD-ядро. Цель — AI-функции и упрощённый UX вокруг готового ядра.
- **Монетизация**: Freemium.

Форк: `FashionFreedom/Seamly2D` → `shadowrunk-cell/Seamly2D`.

## 2. Форматы файлов (что мы обрабатываем)

Понимание форматов — фундамент для автоматизации и хранения шаблонов.

| Расширение | Назначение | Формат |
|---|---|---|
| `.val` | шаблон выкройки (исторический) | текст / XML |
| `.sm2d` | шаблон выкройки (новый, в Сеамли после ~2023) | текст / XML |
| `.vit` | мерки конкретного человека | текст / XML |
| `.vst` | коллекция мерок (группа размеров) | текст / XML |
| `.smis` / `.smms` | индивидуальные / мультиразмерные мерки | текст / XML |

Подтверждение из исходников форка (`src/libs/vmisc/def.cpp:190-195`):

```
valExt = "val";  vitExt = "vit";  vstExt = "vst";
sm2dExt = "sm2d"; smisExt = "smis"; smmsExt = "smms";
```

То есть **наш форк уже понимает `.sm2d`** — это не «чужой» формат. `.sm2d` использует и
SeamlyMe (`src/app/seamlyme/tmainwindow.cpp:1641`). Это позволяет:
- хранить новые шаблоны в `.sm2d` (современный стандарт) и
- при желании конвертировать `.val` → `.sm2d` автономно (см. `src/libs/ifc/xml/vpatternconverter.cpp`).

**Как это устроено внутри** (важно для генерации):
- Шаблон `.val`/`.sm2d` содержит конструктивные точки, линии, сплайны, детали и
  **ссылки на переменные из файла мерок** (имена мерок вроде `bust_circ`, `waist_to_hip_b`).
- Файл мерок `.vit` — XML с телом `<body-measurements><m name=... value=.../>`.
- Когда меняется значение в `.vit`, Seamly2D перестраивает всю геометрию выкройки
  (параметрическая зависимость). На этом строится наш конвейер генерации: подставить мерки
  в `.vit` → Seamly пересчитает чертёж → экспорт в готовый файл.

## 3. Технологический стек и архитектура (текущая)

```
┌─────────────────────────────────────────────────────────────────┐
│  SeamlyAI                                                       │
│                                                                 │
│  ┌────────────────────┐    ┌───────────────────────────────┐    │
│  │  C++/Qt core        │    │  AI-Service (Python/FastAPI)  │    │
│  │  (форк Seamly2D)    │    │                               │    │
│  │  читает/пишет       │◄──►│   - LLM-чат (text + vision)  │    │
│  │  .val/.sm2d/.vit    │    │   - генерация лекал по шаблонам│   │
│  └────────────────────┘    │   - провайдер-абстракция       │    │
│                            └───────────┬───────────────────┘    │
│                                        │                        │
│                            ┌───────────▼───────────────────┐    │
│                            │  Веб-UI (React/TS, future)    │    │
│                            └───────────────────────────────┘   │
│                                                                 │
│  3D: DXF-ASTM / OBJ / FBX  →  CLO 3D, Blender                  │
└─────────────────────────────────────────────────────────────────┘
```

### Основные слои:
1. **Core (C++/Qt)** — унаследован от Seamly2D. Мы его почти не трогаем.
   Умеет headless-режим (CLI): разбор и экспорт без GUI.
2. **AI-Service (Python/FastAPI)** — вся наша новая ценность:
   - `app/providers/` — абстракция LLM (OpenAI-compat + Anthropic)
   - `app/pattern/` — генерация лекал (шаблоны, мерки, adjustments)
   - `app/routes/` — REST API
   - `app/static/` — веб-чат (MVP на HTML/JS)
3. **templates/** — реальные `.val`-шаблоны (лифы, юбки, брюки, корсеты) с метаданными
   (вид, пол, картинка-превью) в реестре `app/pattern/templates.py`.

## 4. Конвейер генерации файла (текущий, синхронный)

```
Мерки (частично)  →  [AI-Service]  →  .vit  (файл мерок)
                                    →  .val  (копия шаблона с подставленными мерками)
```

- AI-Service получает мерки пользователя и шаблон.
- Недостающие мерки выводятся из базовых (ОГ/ОТ/ОБ/рост) или из стандартного размера
  (`app/pattern/measurements.py`).
- Генерирует `.vit` и подставляет имя файла мерок внутрь шаблона, корректирует инкременты
  (`app/pattern/generator.py`).
- Результат — валидный XML, совместимый с Seamly2D.

**Ограничение текущей стадии**: PDF/DXF/SVG мы пока не рендерим — только отдаём
`.val`/`.vit`/XML. Экспорт в готовые форматы — задача появления рабочего контейнера Seamly2D.

## 5. Контейнер Seamly2D (главный блокер к «PDF пакетно»)

Seamly2D имеет **полноценный headless CLI** (без GUI). Это то, что нужно для контейнера:

```
Seamly2D [--test <file>] [-p <index>] [-d <dir>] [-b <basename>]
         [-m <file.vit|vst|smis|smms>] [--gsize <n>] [--gheight <n>] <pattern>
```

- `--test <file>` — валидировать/пересчитать паттерн и завершиться.
- `-m <file>` — подставить файл мерок (`.vit`/`.vst`/`.smis`/`.smms`).
- `-d <dir>` / `-b <name>` — каталог и базовое имя выходных файлов.
- Экспорт (headless): DXF (AAMA/ASTM/flat), PDF, SVG, PNG, TIF, JPG, BMP, EPS, PS, OBJ.
- Для EPS/PS на рантайме нужен `pdftops` (poppler).

Реализация разбора флагов — `src/app/seamly2d/core/vcmdexport.cpp`,
окно без GUI — `src/app/seamly2d/core/mainwindowsnogui.cpp`,
диспетчеризация — `MainWindow::processCommandLine()` (`src/app/seamly2d/mainwindow.cpp:7848`).

**План**: обернуть этот CLI в минимальный Linux-образ. API принимает «команду» (шаблон +
мерки + формат), вызов подставляет `.vit` и возвращает готовые файлы в ответе.
Этот контейнер затем вызывается из Celery-worker (см. §7).

## 6. Ключевые архитектурные решения

### Решение 1: Провайдер-агностик (не хардкодим LLM)
- **Почему**: у пользователя много провайдеров (OpenCode, локальные модели, Сбер/GigaChat, Ollama, Azure, vLLM).
- **Как**: конфиг `providers.yaml` описывает провайдеров и роли моделей (`text`, `vision`, `image`).
  Никакого хардкода конкретной модели в коде. Одна модель может закрывать несколько ролей.
- **Сильные стороны**: смена LLM = правка YAML, без пересборки.
- **Открытый вопрос**: нет API-ключа-агностика по умолчанию; ожидаем ключ из env.

### Решение 2: Генерация лекал "по шаблонам", а не свободный VIT
- **Почему**: свободная генерация VIT ненадёжна. Шаблоны дают рабочий результат сразу.
- **Как**: берём реальный `.val`/`.sm2d` → заменяем мерки в `.vit` и применяем уточнения (adjustments).
  Результат — валидный XML, который открывается в Seamly2D.
- **Сильные стороны**: детерминированно, работает без LLM, тестируемо офлайн.
- **Открытый вопрос**: нужен ли авто-обвес ткани (outline/flip по контуру) — Phase 2.

### Решение 3: Разделение ядра и AI-слоя
- **Почему**: чтобы не тащить вечную синхронизацию с upstream (это острая боль форков).
- **Как**: AI-сервис — отдельный микросервис, не зависит от кода Seamly. Upstream обновления
  тянем редко и адресно (только полезные фиксы вроде экспорта).
- **Сильные стороны**: AI не ломается от обновлений C++ ядра; можно развивать независимо.

### Решение 4: Каждая фаза — отдельная итерация с OpenSpec
- Полная цепочка: `proposal → task → spec` в `openspec/`. Validate OpenSpec в CI.

### Решение 5: Хранение шаблонов — репозиторий сначала, облако потом
- **Сейчас**: `.val`/`.sm2d`-файлы лежат в `ai-service/templates/`, метаданные (вид, пол,
  картинка) — в Python-реестре `templates.py`. Каталог отдаётся через `GET /api/patterns/templates`.
- **Потом**: перенос метаданных в БД (см. §7), при масштабировании — объектное хранилище
  (Yandex Cloud / Selectel S3) для самих файлов.
- **Источники наполнения**: реальные выкройки (Mandy Barrington, The Shapes of Fabric,
  Darragh Starr), облако сообщества my-pattern.cloud. **Важно**: проверить лицензии на
  использование загруженных выкроек перед публикацией их в каталоге.

## 7. Целевая инфраструктура (крупная картина + фазы)

Предложенный целевой стек соответствует духу наших задач, но вводится **поэтапно**, чтобы не
тащить всю инфраструктуру на MVP.

```
                ┌────────────────────────────────────────────────┐
                │             Docker Compose                      │
                │                                                  │
  React SPA ──► │  FastAPI (API) ──► Redis ──► Celery Worker      │
                │       │                    │                     │
                │       ▼                    ▼                     │
                │  PostgreSQL          Container: Seamly2D CLI     │
                │  (пользователи,       (генерирует .vit → PDF/   │
                │   заказы,            DXF/SVG/PNG, возвращает)    │
                │   метаданные                                    │
                │   шаблонов)         S3 (Yandex/Selectel)         │
                │                       (файлы шаблонов, готовые   │
                │                        выкройки)                 │
                └────────────────────────────────────────────────┘
```

### Роли компонентов (целевая картина)
| Компонент | Роль |
|---|---|
| React/Vue SPA | каталог шаблонов, форма мерок, «Сгенерировать», скачивание PDF |
| FastAPI (API) | «мозг»: валидация, ставка задач в очередь, автодоки `/docs` |
| Celery (Worker) | длительные задачи: `.vit` → вызов Seamly2D → PDF, оповещение о готовности |
| Redis (брокер) | очередь задач для Celery + кеш часто используемых шаблонов |
| PostgreSQL | пользователи, заказы, метаданные шаблонов (название, категория, пол, цена) |
| Container Seamly2D | headless-рендер выкроек |
| S3 | файлы шаблонов и готовых выкроек при масштабировании |

### Фазовый план внедрения

1. **Phase 3g — Контейнер Seamly2D (сейчас, blockere)**:
   минимальный Linux-образ + headless CLI; API «команда → файл» (PDF/DXF/SVG/PNG).
   Без очереди — синхронно, для MVP.
2. **Phase 3h — Async-фабрика (Celery + Redis)**:
   когда рендер становится тяжёлым/массовым — переводим задачу в очередь,
   возвращаем `job_id`, клиент опрашивает статус. Добавляем fastapi `BackgroundTasks`
   как промежуточный шаг и Celery — как полноценный.
3. **Phase 4 — UI (React/TS)**: каталог + форма + статус задачи + скачивание.
4. **Phase 7 — Данные/мультипользовательство**: PostgreSQL (пользователи, заказы,
   метаданные шаблонов), перенос реестра `templates.py` → БД, S3 для файлов.
5. **Phase 5 — Монетизация** (Freemium) поверх заказов/лимитов.

> Замечание: Celery+Redis и PostgreSQL — это обоснованно на этапе
> «несколько пользователей + массовый рендер PDF». Для текущего MVP
> (1 пользователь, одиночная генерация .val/.vit) они избыточны, поэтому
> вводятся фазой (3h и 7), а не сразу.

## 9. Открытые вопросы (кандидаты на ревью-фидбек)

1. **Синхронизация с upstream** — как правильно и автоматически тянуть обновления Seamly2D
   и не сломать собственные изменения. Rebasing vs merge стратегия.
2. **Безопасность провайдеров** — управление API-ключами (env, secrets-менеджмент, vault).
   providers.yaml содержит ключи — есть риск утечки. Нужен ли менеджер секретов?
3. **Валидация лекал** — как тестировать, что сгенерированный `.val`/`.sm2d` корректен в
   Seamly2D без ручного открытия? (golden-файлы, container-smoke `--test`, снэпшот-тесты.)
4. **Vision-пайплайн** — как надёжно переводить фото/эскиз в мерки (замеры с фото?).
5. **Масштабирование** — YAML/БД-шаблоны лекал: API для добавления новых шаблонов без кода.
6. **Роли моделей** — хватает ли text/vision, нужен ли отдельный "planner"/"router" для LLM
   (последовательность шагов: промпт → каркас лекала → финал)?
7. **`.sm2d` vs `.val`** — вводить ли авто-конвертацию существующих `.val` в `.sm2d` как
   canonical-формат каталога, или хранить оба и конвертировать на лету?
8. **Лицензии шаблонов** — какой набор выкроек (вкл. my-pattern.cloud) легально в каталог?
9. **Рендер PDF в контейнере** — хватает ли poppler (pdftops), или нужен полноценный
   Qt-стеk в образе для печати выкроек с коэффициентом масштаба?

## 10. Файлы для точечного ревью

- `ai-service/app/pattern/generator.py` — ядро генерации лекал (regex-подстановка в XML).
- `ai-service/app/pattern/measurements.py` — стандартные размеры, вывод производных мерок.
- `ai-service/app/pattern/templates.py` — реестр шаблонов-изделий (категория, пол, картинка).
- `ai-service/app/providers/*.py` — адаптеры LLM.
- `ai-service/app/routes/*.py` — REST API (в т.ч. каталог `/api/patterns/templates`).
- `ai-service/providers.example.yaml` — пример конфигурации провайдеров.
- `ai-service/tests/test_generator.py` — офлайн-тесты (без LLM).
- `src/app/seamly2d/core/vcmdexport.cpp` / `mainwindowsnogui.cpp` — headless CLI.
- `src/libs/vmisc/def.cpp` — константы расширений (`.val`, `.sm2d`, `.vit`, ...).
- `src/libs/ifc/xml/vpatternconverter.cpp` — конвертация форматов паттерна.
- `openspec/project.md`, `openspec/AGENTS.md` — цель и правила.
